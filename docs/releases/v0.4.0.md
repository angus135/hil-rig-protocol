# v0.4.0 release preparation and integration handoff

This stack prepares the protocol release. The PRs remain unmerged. No v0.4.0
tag, GitHub release or public package publication is created by this work.
Firmware, downstream application orchestration and hardware validation are
outside this repository task. Codec tests establish serialization and local
validation; the endpoint conversations below describe required integration.

`RunOutcome.REJECTED=4` is part of v0.4.0 Run Report schema 1. Because there
are no older consumers of this pre-release wire contract, it does not require a
protocol-version or schema-version increment.

## Changes and compatibility

| Requirement | Protocol delivery |
| --- | --- |
| P1 | u16 spans; 4096-byte default and 65535-byte absolute complete-message limits; eight chunks per tick; retained 255-byte legacy fields; build outputs removed. |
| P2–P3 | Run Report type 35, schema 1, exact 177 + E body; shared stable failure enums; explicit result-stream termination and validity rules. |
| P4–P5 | Rig Status type 50; GET_STATUS command 2; truthful readiness, query correlation and reset/abort ordering contract. |
| P6 | Matching C11 records, sizing/validation/encode/decode, immutable typed Python records, CFFI parity, exports, examples and ownership tests. |
| P7 | Version 0.4.0, ABI migration, distribution verification and existing CI gates. |
| P8 | Bidirectional Arbitrary Control/Data types 64/65, endpoint-defined u32 IDs, opaque data, ping/echo examples. |

→ the release-readiness PR based on #53. Later branches contain all earlier
changes. Record the final merged commit when pinning firmware or building a
source artifact. Use the v0.4.0 tag only after that commit is on the release branch.

Application discovery must confirm exactly 0.4.0 per Transport session before
ordinary traffic. Update the firmware protocol pin and rebuild firmware;
Callum's Python environment requires `hil-rig-protocol==0.4.0`. Rebuild all native
consumers and CFFI extensions; see [ABI migration](../versioning.md).
Do not combine an old native extension with new Python declarations.

The protocol's 4096-byte default is independent of Transport's 512-byte default.
Configure both layers to an agreed complete-message ceiling. The inspected MCU
Application buffer is 2302 bytes; direct USB's two-byte length prefix is outside
that ceiling. An 8192-byte decode workspace does not increase it. Chunk records
accordingly and retain the eight-chunk-per-tick limit. A representable 65535-byte
span is too large once its envelope, record header and padding are added.
Discovery/configuration/error/report one-byte extensions remain at most 255.
Enabled I2C remains unsupported; reserved identifiers remain reserved.

## Release checks and artifacts

Run the existing seven CI workflows on every PR head: clang-format, C unit
tests, C integration tests, C build options, Python quality, Python unit tests
and Python distributions. They cover existing Debug/Release options, public C11
consumers, Linux and Windows Python 3.12–3.14 wheels, sdist contents, version
parity and installed-wheel consumers. No additional platform matrix is required.

Useful local gates, from the source root:

```sh
python scripts/check_version.py
python -m build --outdir <artifact-directory>
python scripts/verify_distribution.py sdist <artifact-directory>/*.tar.gz
python scripts/verify_distribution.py wheel <artifact-directory>/*.whl
python -m twine check <artifact-directory>/*
```

Also build a wheel from the extracted sdist without Git metadata, install it in
a fresh virtual environment outside this checkout and run
`python scripts/run_installed_tests.py --project-root <source-root>`. Check
Debug and Release CTest runs and a shared-library install/consumer build.
Compare v0.3.0 and v0.4.0 public layouts with `scripts/check_application_abi.py`;
the size-field width change must require a new ABI generation.

The existing `python-wheels.yml` builds and uploads CI artifacts, including on
matching tags. It does not create a GitHub release or upload to PyPI. After the
stack is merged and approved for release, validate `v0.4.0` against VERSION,
create the tag through the repository's release process, obtain passing tag
artifacts and explicitly publish them through the project's chosen channel.
Until then install a verified local/CI wheel with
`python -m pip install <hil_rig_protocol-0.4.0-wheel>`; do not assume an index
already contains this version.

## MCU integration still required

No MCU code was changed or hardware scenario demonstrated. The firmware owner
must implement/verify each applicable path rather than infer support from codec
coverage:

1. Update the protocol submodule/pin and Application capacity configuration;
   keep USB, clocks, scheduling and physical I/O in firmware.
2. Map authoritative lifecycle state to Rig Status, including optional active
   identity, flags and failure provenance. Send the initial truthful status
   after discovery, readiness transitions, and one captured response per query.
3. Preserve the resolved START identity, including rejection, seal one terminal
   metadata snapshot, translate native faults using the documented stable
   mapping, and queue its report after all emitted results before releasing
   storage. No stale snapshot may be relabelled with a new Test ID.
4. Snapshot execution-phase flash statistics before final drain, stop ISR
   sampling before sealing, preserve u64 totals and invalidate a whole section
   on unrepresentable counters. Never invent measurements for missing ticks.
5. Implement wrong-ID rejection, fault recovery and destructive-reset ordering
   as documented in [endpoint lifecycle](../application_layer/application_messages.md#endpoint-lifecycle-and-recovery).
6. Add endpoint ping (ID 1, value 42 → ID 1 data containing LE u32 42) and echo
   (ID 2, opaque bytes returned unchanged) if useful. These IDs are example
   conventions; the codec accepts all u32 IDs and executes no handler.

Native `RSM_EXTERNAL_REQUEST` alone does not prove host abort: use a validated
host-origin indication, otherwise map to INTERNAL_FAILURE. Capture the first
failure's stage when it occurs. Later reset/cleanup failure must not overwrite
that provenance or cause a second terminal report.

## Callum's host and board checklist

Use the public Python records/codecs. Persist the Run Report alongside results;
keep per-tick PARTIAL separate from run-level PARTIAL. Stop waiting at a report,
discard an unfinished trailing tick, preserve raw cycle counts and convert time
only using independently established clocks. Do not treat Transport ACKs as
semantic success or Rig Status notifications as command responses.

Validate exact discovery, GET_STATUS while ready/busy/faulted, success, early
failure with fewer than N results, preparation/finalisation/transfer failures,
abort, wrong-ID abort, fault reset, refused/pending reset, connection loss and
late responses. A host reset wait may use a finite caller-owned deadline (for
example 16 seconds), while still servicing Transport/status; no protocol clock
or blocking wait is added to the library.

Run sequential tests using fresh uploads and fresh Test IDs. Demonstrate that no
old report appears under the next ID, and readiness permits immediate admission
of the next configuration. Full-system tests, storage/UI work, calibration,
retained-test replay and new run identifiers remain downstream work.
